## تغيير جديد: دخول المدير وخروجه

- `/admin` يحوّل الزائر إلى `/admin/login`، ويعرض اللوحة بعد تسجيل الدخول بحساب البيئة الحالي فقط.
- جلسة عشوائية لمدة 12 ساعة؛ يحفظ الخادم hash الرمز وربطاً ببيانات الاعتماد الحالية. تغيير اسم المدير أو كلمة سره يبطل الجلسات السابقة عند الطلب التالي.
- Cookie: HttpOnly، SameSite=Strict، Path=/admin، وSecure على الدومينات العامة حتى خلف proxy ينهي TLS. الاستثناء HTTP المحلي للتطوير فقط.
- تسجيل الخروج POST يلغي الرمز في الخادم ويمسح Cookie. إعادة استخدام الرمز بعد الخروج تُرفض. إعادة تسجيل الدخول تبدّل الرمز وتلغي السابق في المتصفح نفسه.
- حماية CSRF القائمة تشمل login/logout: ترويسة X-Panel-Request وفحص Origin وعدم إتاحة CORS مفتوح.
- 30 محاولة دخول خلال خمس دقائق لكل IP، بالإضافة إلى حد الطلبات الإداري العام؛ لا تُسجّل كلمات السر أو الرموز.
- عند 401 تعود الواجهة إلى الدخول؛ يُعاد التحقق عند استرجاع الصفحة من ذاكرة المتصفح.
- تستمر HTTP Basic للـAPI عند إرسال Authorization صراحةً، لتوافق أدوات الإدارة السابقة. واجهة المتصفح لا تطلب Basic ولا تعتمد عليه. Logout يلغي جلسة المتصفح، ولا يغير كلمة السر أو يلغي صلاحية عميل API يرسل بيانات اعتماد صحيحة صراحةً. عند وجود Cookie غير صالح لا يجري fallback إلى Basic.
- إضافة جدول `admin_sessions` وفهرس فقط؛ لا تغيير بجداول الأجهزة والاشتراكات والأرصدة، ولا تعديل .env. Dockerfile يشمل الوحدة الجديدة.

## التحقق

- قبل التغيير: 37/37 اختبار بانل ناجح محلياً.
- بعد التغيير: 45/45 اختبار ناجح محلياً. الثمانية الجديدة تختبر الإلغاء وإعادة استخدام الرمز، انتهاء الجلسة وتدويرها وتغيير بيانات الاعتماد، CSRF، أعلام Cookie خلف proxy، rate limit، عدم إرجاع الأسرار، توافق Basic، استمرار الجلسة بعد reload، والحفاظ على بيانات جهاز مصطنع.
- تحديث اختبار الواجهة لاستخدام نموذج دخول المدير فعلياً عند عرضي 390 و1366، وفحص الخروج ورفض إعادة الرمز. يستمر فحص المظهرين وMAC ودخول الموزع وتفعيله وخروجه وPIN والقوائم.
- Chromium المحلي غير متاح للتشغيل في هذا الصندوق بسبب منع sockets؛ اختبار المتصفح والحاوية يُنفّذ في GitHub Actions. لا تُنسب له نتيجة نجاح حتى ينتهي التشغيل البعيد.
- اختبارات API تستخدم قواعد مؤقتة فقط. لم تُستخدم قاعدة بيانات الخدمة الحالية أو نسختها؛ اختبار الترحيلات على نسخة خاصة من مخطط الإنتاج يبقى شرط نشر.

## ما تأكد في Android وما بقي

قراءة الكود الحالي أكدت أولوية FFmpeg للصوت على TV/الأجهزة دون لمس فقط، وبقاء مسار الهاتف وMediaCodec للفيديو. FFmpeg يبنى من مصدر مثبت لـAPI24؛ الـAAR الجاهز الذي يتطلب API26 لا يُستخدم. Coil على TV محدود إلى 6 طلبات/3 لكل مضيف و10% RAM مع مهلة ومحاولتين إضافيتين. توجد استعادة تركيز Live وتحديث الصور وحراسة إذن التثبيت API26.

لم يتغير Android في PR الجلسات. فُحصت نتائج Actions للرأس الحالي مباشرة: البناء الموقّع [43586681486](https://github.com/youdibstar/sega-player-final-edition/actions/runs/43586681486)، التحقق الكامل [43586685282](https://github.com/youdibstar/sega-player-final-edition/actions/runs/43586685282)، وUI [43586681469](https://github.com/youdibstar/sega-player-final-edition/actions/runs/43586681469)، كلها ناجحة. خطوة توقيع شهادة المالك نجحت. لا تساوي هذه النتائج نجاح سماع الصوت أو قياس RAM على جهاز حقيقي.

فحص إضافي وجد `java.nio.file.Files.move` في تثبيت التحديث رغم استخدام desugar_jdk_libs الافتراضي، الذي لا يتضمن nio. يُعالج هذا في تغيير Android مستقل مبني على #14، دون استبدال محرك الفيديو أو مسار الصوت.

## فجوات لا يجوز إخفاؤها

1. مخطط `resellers.py` في الفروع القديمة يختلف عن `reseller.py` الحالي. الحسابات الفرعية/أنصاف النقط/مدد التفعيل في #3، والتدقيق والنسخ الاحتياطي في #6، ليست ميزات مندمجة لمجرد وجود صفحاتها في فرع قديم. لا تُنسخ جداولها أو تُبدّل وحدات البانل فوق البيانات الحالية دون ترحيل مختبر. هذه تبقى فجوة تكامل، ولم تُحل في تغيير الجلسات.
2. pagination الإدارة الموجودة في فروع Android القديمة ليست في بانل main الحالي؛ تحميل جميع الأجهزة قابل للتباطؤ عند تضخم البيانات. يلزم تكامل مع API الحالية واختبار حجم مستقل.
3. النسخ الاحتياطي/الاسترجاع من الواجهة وسجل شامل لكل عمليات المدير غير موجودين في المسار الحالي. `reseller_ledger` يغطي الأرصدة، ولا يُعد سجلاً شاملاً لكل العمليات.
4. لم يُنجز فحص CVE شامل لكل اعتماد. نطاقات إصدارات Python واسعة؛ تثبيتها وفحصها يحتاجان تحديثاً مستقلاً مع اختبار توافق.
5. التفعيل السنوي الحالي للموزع يخص رخصة المشغل؛ لا يوجد بيع لقنوات أو اشتراك IPTV. تجارب الإدارة/الدائم لا تُثبت سياسة حساب أنصاف النقط القديمة.
6. الحقوق التجارية وLGPL وإمكانية إعادة الربط مع فحص شهادة المالك تحتاج مراجعة توزيع؛ وجود مصدر FFmpeg والإشعارات شرط عملي لكنه لا يحسم كل التزامات التوزيع.
7. لم يُفحص إعداد SSL أو proxy أو المنافذ أو النسخ الاحتياطي الفعلي على sega-311/sega-test، احتراماً لمنع تعديل الإنتاج. لا توصف بأنها مُختبرة على الخادم.

## النشر والتراجع

هذا الفرع فوق PR #15، وليس بديلاً لـPR #14 الخاص بالتطبيق. يُراجع #15 أولاً ثم تغيير الجلسات. تحديث البانل يجب أن يشمل admin_auth.py وmain.py وملفات الواجهة وDockerfile معاً. قبل أي إذن نشر لاحق: نسخة SQLite متسقة، integrity_check، وتجربة startup على نسخة من المخطط الفعلي، ثم مقارنة الأجهزة والأرصدة والاشتراكات. لا تُنسخ قاعدة اختبار إلى الإنتاج ولا تُستبدل .env.

عند التراجع للكود السابق يبقى جدول admin_sessions الإضافي دون ضرر؛ لا حاجة لحذف البيانات. لا يُعاد ملف قاعدة قديم فوق معاملات أحدث. تبقى تعليمات النشر التفصيلية في التقرير السابق تعليمات فقط، وليست عمليات منفذة.
