# SEGA PLAYER V3 0.5.16 — تحديث متوافق للتطبيق واللوحة

هذا الفرع مبني على 0.5.15، ويحافظ على تحسين ترتيب القنوات بسرعة وإدارة الأجهزة المرقمة؛ يضيف نظام الموزعين وحماية تعديل/حذف القوائم الشخصية بواسطة PIN.

## سبب عطل 0.5.15
كان Android يوقف التسجيل إذا فشل GET /api/v1/time بالرمز 404. في 0.5.16 أصبح فحص التوقيت اختيارياً، مع إبقاء توقيع الطلبات والأمان. بعد نشر لوحة 0.5.16 يستقبل التطبيق unix_seconds بتوقيت UTC الصحيح.

## الاختبار والنشر
1. لا تستبدل بيانات الإنتاج أو ملفات DATABASE_PATH أو SECURITY_DATABASE_PATH أو إعدادات حماية التوقيع. خذ نسخة SQLite متسقة مع WAL مسبقاً.
2. انشر مجلد panel **كاملاً** على staging: main.py وresellers.py وكل static وdependencies. لا تنشر main.py وحده، لأن واجهة مدير الأجهزة تغيرت وأصبحت تعتمد على API صفحات.
3. تحقق من GET /health وGET /api/v1/time (unix_seconds)، ثم جرّب POST /api/v1/register وGET /api/v1/config بهوية اختبار جديدة، وبعدها /admin و/portal و/reseller و/admin/resellers.
4. تأكد من أن رصيد الموزعين والتفعيلات لا تخصم مرتين. PIN يلزم لتعديل/حذف القائمة الشخصية فقط وليس للمشاهدة.
5. جرّب Android 0.5.16 الموقّع بمفتاح المالك الأصلي فوق 0.5.15 مع الحفاظ على بيانات التطبيق. لا تحذف التطبيق ولا مفتاح الجهاز.
6. بعد نجاح اختبارات CI والتجربة الميدانية، ارفع sega-34.apk إلى مسار التحديث ثم latest.json **بالترتيب**، ولا تنشر هذه الملفات تلقائياً من الفرع التجريبي.

## التوافق
- /api/v1/time يرد على 0.5.15 بـ unix_seconds بالإضافة لحقول unix وtimestamp العامة.
- الجهاز يستعمل نفس MAC الافتراضي وDevice Key؛ API /api/v1/config لا ترجع أسرار PIN.
- حماية trial_token وتوقيع Android ServerClock من 0.5.15 محفوظة.
- المسارات القديمة للتسجيل والتفعيل لم تتغير؛ لا تحتاج PIN لمشاهدة قنوات IPTV.
